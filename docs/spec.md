# spec.md — SDVC 웹서비스 명세

> 작성일: 2026-09-10 · [P1-1] Specify · WBS v2.0(`10_SDVC_웹서비스/WBS_서버구축.md`)를 재료로 작성

## 한 줄 정의

브라우저 로그인만으로, 설치 없이, SDVC 방법론(헌장→명세→계획→작업분해→TDD구현)을 AI와 함께 진행해 프로젝트(예: 홈페이지)를 만들고, 완성된 결과물을 고유 URL로 바로 열람할 수 있는 유료 웹서비스.

## User Story

### 개발자 (SDVC의 유료 고객)

| ID | 우선순위 | 내용 | 관련 Phase |
|---|---|---|---|
| US-D1 | P1 | 개발자로서, 이메일로 가입·로그인해 SDVC 콘솔에 들어갈 수 있다 | Phase 2 |
| US-D2 | P1 | 개발자로서, AI와 대화하며(헌장→명세→명확화→계획★승인→작업분해★승인→구현) 프로젝트를 만들 수 있다 | Phase 3 |
| US-D3 | P1 | 개발자로서, 대화 도중 창을 닫아도 다음에 이어서 진행할 수 있다 | Phase 3 |
| US-D4 | P1 | 개발자로서, AI가 만든 파일이 저장되고 진행 상황을 볼 수 있다 | Phase 4 |
| US-D5 | P1 | 개발자로서, 완성된 프로젝트를 고유 URL로 열람하고 공개범위(비공개/링크공개/전체공개)를 정할 수 있다 | Phase 5 |
| US-D6 | P2 | 개발자로서, 체험 7일이 지나면 결제해야 계속 쓸 수 있다 | Phase 6 |
| US-D7 | **P2** | 개발자로서, 내 프로젝트의 버그를 프롬프트로 설명하면 SDVC 엔진이 직접 고쳐준다 | Phase 7 |
| US-D8 | **P2** | 개발자로서, 이미 만든 프로젝트에 기능을 추가 요청할 수 있다 | Phase 7 |
| US-D9 | P3 | 개발자로서, 수정이 잘못됐을 때 이전 버전으로 되돌릴 수 있다 | Phase 7 |
| US-D10 | P3 | 개발자로서, SDVC 플랫폼 자체의 문제를 서버관리자에게 신고할 수 있다 | Phase 7→8 |
| US-D11 | P3 | 개발자로서, 완성된 프로젝트를 zip으로 내려받을 수 있다 | Phase 9 |
| US-D12 | **MVP 제외(향후)** | 개발자로서, 내 산출물에 사용자 로그인(ID/비밀번호)을 넣고, 그 회원을 등록·삭제 등으로 직접 관리할 수 있다 — "산출물 회원기능". 2026-09-08 MVP 제외 결정, 2026-09-10 범위 재확인(MVP 이후 유지) | Phase 9 이후(별도 설계 필요) |
| US-D13 🆕 | **P1** | 개발자로서, 프로젝트를 한 번 완성한 뒤에도 같은 대화에서 계속 고치고 기능을 더할 수 있다 — "대화가 끝났습니다"로 막히지 않는다 | 슬라이스 6 |
| US-D14 🆕 | P2 | 개발자로서, 프로젝트 이름을 만들 때 정하고 나중에 바꿀 수 있다 | 슬라이스 6 |
| US-D15 🆕 | P2 | 개발자로서, 프롬프트에 파일·이미지를 첨부해서 설명할 수 있다 (말로 설명하기 어려운 것을 보여준다) | 슬라이스 7 |
| US-D16 🆕 | P2 | 개발자로서, 첨부한 이미지를 내 홈페이지에 실제로 넣을 수 있다 | 슬라이스 7 |
| US-D17 🆕 | **P1** | 서버관리자로서, **관리자 전용 입구**로 들어가고 개발자 화면과 구별되는 화면에서 일한다 — 남의 계정을 손보는 중인지 내 프로젝트를 보는 중인지 헷갈리지 않는다 | [P8-11] |
| US-A6 🆕 | **P1** | 서버관리자로서, 개발자들이 만든 모든 프로젝트를 **유지보수 차원에서** 보고 필요하면 직접 열어볼 수 있다 — 공개범위와 무관하게 | [P8-13] |
| US-D18 🆕 | **P1** | 서버관리자로서, 쌓인 감사 기록을 **화면에서 직접 본다** — 누가 무엇을 했는지 확인하려고 개발자를 부르지 않는다 | [P8-7] |
| US-D10 ✅ | P3 → **P2** | (기존) 개발자로서 플랫폼 문제를 신고한다 — Clarify 17에서 접수함과 함께 만들기로 미뤄둠 | [P8-5] |
| US-A3 ✅ | P3 → **P2** | (기존) 서버관리자로서 신고를 접수·처리한다 | [P8-5] |
| US-D19 🆕 | P3 | 개발자로서, "휴대폰에 앱처럼 설치되게 해줘"라고 요청하면 산출물이 홈 화면에 설치되고 오프라인에서도 열리게 할 수 있다 (네이티브 앱은 아니다) | [P7-13] |

> **2026-09-11 사용자 재확인**: "개발자 모드에서 개발자는 자신이 개발한 프로젝트의 버그 수정과 추가 기능 요구를 SDVC의 Claude Code에게 할 수 있어야 한다." → US-D7·US-D8을 P3에서 **P2로 상향**하고, 진입점(FR-025)을 추가함. 본체(버그 등록·추적, 버전 롤백)는 Phase 7 그대로.
>
> **2026-09-12 사용 중 발견 5건 반영**: 진입점(FR-025)은 만들었지만 **실제로는 쓸 수 없었다** — 구현을 마친 대화는 `done` 상태가 되어 모든 입력이 막혔다(US-D13). 이와 함께 프로젝트 이름 지정·변경(US-D14), 프롬프트 첨부(US-D15), 산출물에 이미지 넣기(US-D16)를 등록한다. 상시 접수는 `docs/backlog.md`가 맡는다.

### 사용자 (개발자가 만든 산출물의 방문자 — SDVC와 직접 계약 없음)

| ID | 우선순위 | 내용 | 관련 Phase |
|---|---|---|---|
| US-U1 | P1 | 사용자로서, 공개되거나 링크를 아는 산출물을 로그인 없이 브라우저로 바로 열람할 수 있다 | Phase 5 |

> **2026-09-12 운영 맥락 확정**: 당분간 **교육용**으로 쓴다(수강생이 직접 실습). 사업 연계는 **반년~1년 뒤**.
> 한국에서 실결제를 받으려면 사업자등록이 전제이므로 **실결제 전환은 그때까지 보류**하고, Stripe는 테스트 모드로 둔다
> (수업에서 결제 흐름을 보여주기에는 오히려 테스트 모드가 낫다). 대신 교육 운영에 필요한 FR-035·036을 추가한다.

| US-A2 | P3 | 서버관리자로서, 개발자별 사용량·API 원가를 모니터링하고 상한을 설정할 수 있다 | Phase 8 |
| US-A3 | P3 | 서버관리자로서, 개발자의 플랫폼 신고를 접수·처리할 수 있다 | Phase 8 |
| US-A4 | P3 | 서버관리자로서, 문제 있는 산출물·계정을 즉시 차단할 수 있다 | Phase 8 |
| US-A5 | P3 | 서버관리자로서, 자기 프로젝트를 만들려면 개발자로 겸직 등록해야 한다(서버관리자 자격으로는 불가) | Phase 9 |

## 기능 요구사항 (FR)

| ID | 내용 |
|---|---|
| FR-001 | 이메일 회원가입·로그인 (개발자), 서버관리자는 별도 절차 + 2단계 인증 |
| FR-002 | 3계층(서버관리자/개발자/사용자) × 계층별 등급에 따른 접근권한 통제 — `docs/permissions.md` 매트릭스 근거 |
| FR-003 | SDVC 대화형 엔진: 헌장→명세→명확화→계획(승인게이트)→작업분해(승인게이트)→구현(TDD)을 웹 채팅으로 진행, 예시 답안 함께 제시 |
| FR-004 | 대화·진행 상태 DB 저장 — 세션이 끊겨도 이어서 진행 |
| FR-005 | AI가 생성한 프로젝트 파일(HTML/CSS/JS)을 Storage에 저장, 버전 보관 |
| FR-006 | 프로젝트별 고유 URL(`/site/{slug}`)로 산출물 서빙 |
| FR-007 | 산출물 공개범위 설정: 비공개 / 링크공개 / 전체공개 (기본값 비공개) |
| FR-008 | 가입 후 7일 체험, 만료 시 서버가 자동으로 접근 차단(클라이언트 판정 아님) |
| FR-009 | Stripe 구독 결제 — 기본(월 $12, 프로젝트 3개·월 200만토큰) / 프로(월 $35, 프로젝트 10개·월 800만토큰) |
| FR-010 | 프로젝트 버그를 프롬프트로 등록 → SDVC 웹 엔진이 재현 테스트(RED) 후 직접 수정 |
| FR-011 | 기존 프로젝트에 기능 추가 요청 → 명세 보완(Specify 재실행) → 계획·구현 |
| FR-025 | 대시보드의 각 프로젝트에서 **그 프로젝트를 만든 대화로 바로 들어가 이어서 수정·추가 요청**을 할 수 있다 (US-D7·US-D8의 진입점) |
| FR-029 🆕 | 구현이 끝난 대화도 **계속 열려 있어야 한다** — 유지보수 상태로 남아 수정·기능추가 요청을 무기한 받는다. 어떤 경우에도 입력이 영구히 막히지 않는다 (US-D13, FR-025의 실현 조건) |
| FR-030 🆕 | 새 프로젝트를 만들 때 이름을 정할 수 있고, 만든 뒤에도 대시보드에서 이름을 바꿀 수 있다 (US-D14) |
| FR-031 🆕 | 프롬프트 입력창에 파일·이미지를 첨부할 수 있다. 허용 형식·용량은 서버가 판정하며, 허용하지 않는 것은 업로드 단계에서 거부한다 (US-D15) |
| FR-032 🆕 | 첨부한 이미지를 산출물에 포함할 수 있다 — "이 이미지를 써줘"라고 하면 그 이미지가 실제 홈페이지 파일로 저장되어 서빙된다 (US-D16) |
| FR-045 🆕 | `/admin`의 개발자 관리 표 아래에 **전체 프로젝트** 표를 둔다 — 개발자(이메일)·프로젝트명·제작일·제작 단계·바로보기 (US-A6) |
| FR-046 🆕 | 최고관리자는 유지보수 목적으로 **공개범위·완성 여부와 무관하게** 어떤 프로젝트든 산출물을 열람할 수 있다. 열람은 감사 기록에 남는다 (US-A6) |
| FR-047 🆕 | 산출물을 PWA(설치형 웹앱)로 만들어 달라는 **명시적 요청이 있을 때만** 매니페스트(`.webmanifest`)와 서비스 워커(`sw.js`)를 함께 낸다. 아이콘은 SVG로만 만들며, 네이티브 앱이 되는 것은 아니라고 정확히 안내한다 (US-D19) |
| FR-042 🆕 | 개발자가 화면에서 신고를 보낸다 — 분류·내용·(선택) 겪은 주소. 접수·처리 상태·운영자 답변을 **같은 화면**에서 본다 (US-D10, FR-013) |
| FR-043 🆕 | 운영자가 접수함에서 신고를 보고 상태를 바꾸고 답을 적는다. 부적절한 산출물은 **그 자리에서 가린다**(FR-016 배선) (US-A3) |
| FR-044 🆕 | 운영자의 답변은 신고한 사람에게 **그대로 보인다** — 내부 메모를 적는 칸이 아니다 (FR-013) |
| FR-041 🆕 | 최고관리자는 `/admin/audit`에서 감사 기록을 **직접 열람**한다 — 누가·언제·누구에게·무엇을 했는지, 거부된 시도 포함. 행위자·대상은 이메일로, 시각은 한국 기준으로 보여준다 (US-D17, FR-017의 실현 조건) |
| FR-038 🆕 | 관리자 화면은 **고정된 주소 하나**(`/admin`)로 들어간다. 로그인하지 않았어도 개발자 로그인으로 튕기지 않고 그 자리에서 관리자 로그인을 받는다. **자격 없는 계정으로 들어온 경우에도 맨 404가 아니라** 지금 어느 계정인지 알리고 계정을 갈아탈 길을 준다 (US-D17) |
| FR-039 🆕 | 관리자 화면은 개발자 화면과 **한눈에 구별**된다 — 상단 띠 반전, "운영 콘솔" 표기, 관리자 등급 표시, 개발자 화면으로 돌아가는 길 (US-D17) |
| FR-040 🆕 | 개발자 화면의 **"서버 관리" 입구는 관리자에게만** 보인다. 누르면 404가 뜰 링크는 그리지 않는다 — 콘솔이 열릴지와 같은 판정을 쓴다 (US-D17, FR-034) |
| FR-037 🆕 | 개인정보 처리방침 한 장을 두고 가입 화면에서 링크한다 — 무엇을 받고·왜 받고·언제 지우는지. 이용약관·환불정책은 사업 전환 때(Phase 10) |
| FR-035 🆕 | 서버관리자가 **결제 없이 등급을 부여**할 수 있다 — 교육·멘토링 용도. 수강생이 체험 한도에서 막히지 않게 한다 |
| FR-036 🆕 | 서버관리자가 **계정별 월 사용 한도**를 따로 지정할 수 있다. 지정하지 않으면 등급 기본값을 쓴다 — 한 사람의 폭주가 전체 비용을 삼키지 않게 |
| FR-034 🆕 | 서버관리자 등급 체계 — 최고관리자(전권) / 운영자(사용자관리·차단 가능, 정책변경 불가) / 지원(읽기 전용). 혼자 운영하더라도 **판정 지점을 한 곳에 모아** 나중에 사람을 쓸 때 되돌아가 고치지 않도록 한다 |
| FR-033 🆕 | 대시보드의 이용 상태(등급·체험 잔여·사용량) 카드는 프로젝트 목록보다 **아래**에 두고, 글자·세로 크기를 줄여 부차 정보로 보이게 한다 |
| FR-026 | 월 토큰 한도(기본 200만 / 프로 800만) 초과 시 **새 대화·생성을 즉시 차단**하고 업그레이드를 안내한다. 이미 만든 산출물 열람은 계속 가능 |
| FR-027 | 체험 7일 만료 후 미결제 시: 산출물 **즉시 비공개 + 10일 유예 후 삭제** (구독 해지는 30일 유예 — FR-023). 유예 중 결제하면 그대로 복구 |
| FR-028 | 가격은 **미국 달러(USD)**로 표시·청구한다 (기본 $12 / 프로 $35) |
| FR-012 | 프로젝트 버전 이력 관리 및 롤백 |
| FR-013 | SDVC 플랫폼 신고 채널(개발자→서버관리자), 처리결과는 신고자에게 표시 |

## 이번엔 만들지 않는 것 (Out of Scope — MVP 기준)

- **산출물 자체의 회원가입·로그인 기능** ("산출물 회원" 등급, FR-020/US-D12) — 개발자가 만든 홈페이지에 방문자 로그인 기능은 MVP에 넣지 않음. 대신 공개범위 3단계로 대체.
  **2026-09-10 재확인**: 나중에(Phase 9 이후) 만들 때는 사용자가 ID/비밀번호로 로그인하고, 그 회원의 등록·삭제 등 관리는 **개발자**가 담당하는 구조로 설계한다 — 서버관리자가 아니라 개발자의 권한임에 주의
- **동적 서버 로직이 필요한 산출물** — MVP는 정적 사이트(HTML/CSS/JS)만 생성. 별도 백엔드가 필요한 웹앱은 향후 과제
- **다국어 UI** — 한국어만
- **모바일 네이티브 앱** — 반응형 웹만 제공
- **SDVC 플랫폼 자체의 버그 수정용 웹 관리화면** — 내 PC의 Claude Code로 수행(P8-8 결정). 2026-09-13 재확인: 이 세션의 모든 고침이 그렇게 이루어졌다
- **팀/조직 단위 계정** — 개발자 1계정 = 1개인. 여러 명이 프로젝트를 공유하는 기능은 없음
- **버그를 건으로 등록·추적하는 장부**(P7-2·P7-3) — 2026-09-13 폐기. ①기록은 이미 대화(무엇을 요청했나)와 버전(그때 파일이 어땠나)에 남는다 ②Clarify 15가 건 조건("뭘 요청했는지 잊는 문제가 실제로 나오면")이 아직 오지 않았다(사용자 6명·프로젝트 1개) ③플랫폼 문제는 [P8-5] 접수함이 이미 받는다. **거기 딸려 있던 SC-008은 폐기하지 않고 [P7-12]로 살렸다** — 그쪽이 실제로 겪은 고통에 닿아 있다
- **서버관리자 등급을 바꾸는 화면** — 판정은 실제로 돈다(`adminCan`, 단위 21건·e2e에서 지원 등급 실계정으로 검증). **없는 것은 등급을 지정하는 화면**이다. `admin_tier` 기본값이 `super`이고, 바꾸려면 DB를 직접 고쳐야 한다. 관리자가 한 명인 동안은 그걸로 충분하다
  *(2026-09-13 [P8-8] 정정: 이전에는 "등급 구분은 틀만 마련"이라고 적혀 있었으나 사실과 달랐다)*
- **2단계 인증(MFA)** — `hasVerifiedMfa`는 [P2-7]에 있으나 **어디에도 배선하지 않았다**. 2026-09-13 건너뛰기로 결정: 관리자가 한 명인데 2단계 인증을 켜면 **휴대폰을 잃는 순간 운영 콘솔에 아무도 못 들어간다.** 복구 수단(백업 코드·두 번째 관리자)을 함께 설계할 때 다시 본다
- **실제 결제** — Stripe **테스트 모드**로만 돈다(`sk_test`). 한국에서 실결제를 받으려면 사업자등록·통신판매업 신고가 전제이고, 기존 Stripe 계정은 국가가 US라 **한국 계정을 새로 만들어야** 한다. 교육용으로 무료 운영하는 동안은 전환하지 않는다(Phase 10)
- **메일·알림 발송** — 발송 인프라가 없다(코드 0줄). 신고 처리 결과·체험 만료 같은 알림은 **화면에서만** 보여준다. 없는 것을 있는 척하지 않으려고 신고 화면은 보내는 곳과 결과 보는 곳을 한 화면에 뒀다(Clarify 37)

> **[P8-8] 이 목록은 검사로 지킨다** (2026-09-13).
> "만들어만 두고 아무도 부르지 않는 코드"가 한 세션에 세 번 나왔다
> (BL-008 `ensureAdminRole` / BL-009 관리자 입구 / BL-013 `setProjectBlocked`).
> **셋 다 단위 테스트는 통과했다** — 단위 테스트는 함수를 직접 부르므로
> 아무도 그 함수를 부르지 않는다는 사실은 드러나지 않는다.
> 그래서 `tests/lib/dormant.test.ts`가 `src/lib`의 export 함수를 훑어
> **새로 잠든 함수가 생기면 막고, 잠을 깬 함수는 목록에서 빼라고 알린다.**
> 기록이 글로만 남으면 낡지만, 검사로 두면 저절로 사실로 유지된다.

| 30 🔄 | 자격 없는 계정으로 로그인한 채 `/admin`에 오면? | **안내한다** (Clarify 27을 뒤집음). 처음엔 404로 숨기려 했으나 같은 주소가 로그아웃하면 로그인 화면을 내주므로 **애초에 숨겨지지 않았다** — 시크릿 창 하나면 누구나 확인한다. 남는 것은 계정을 여러 개 쓰는 운영자가 막다른 길에 갇히는 손해뿐. **API 라우트의 404는 유지** — 기계가 두드리는 자리에는 안내할 사람이 없다 | FR-038 |
| 31 | 화면 열람 기록이 나머지를 파묻는다 (실물 8건 중 5건) | **지우지 않고 접는다.** 열람도 증거다(Clarify 20). 다만 **몇 건 접었는지는 밝힌다** — 감췄다는 사실까지 감추면 그게 감사 기록의 구멍이다 | FR-041 |
