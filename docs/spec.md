# spec.md — SDVC 웹서비스 명세

> 작성일: 2026-09-10 · [P1-1] Specify · WBS v2.0(`10_SDVC_웹서비스/WBS_서버구축.md`)를 재료로 작성

## 한 줄 정의

브라우저 로그인만으로, 설치 없이, SDVC 방법론(헌장→명세→계획→작업분해→TDD구현)을 AI와 함께 진행해 프로젝트(예: 홈페이지)를 만들고, 완성된 결과물을 고유 URL로 바로 열람할 수 있는 유료 웹서비스.

## User Story

### 개발자 (SDVC의 유료 고객)

| ID | 우선순위 | 내용 | 관련 Phase |
|---|---|---|---|
| US-D1 | P1 | 개발자로서, 이메일로 가입·로그인해 SDVC 콘솔에 들어갈 수 있다 | Phase 2 |
| US-D2 | P1 | 개발자로서, AI와 대화하며(헌장→명세→명확화→계획★승인→작업분해★승인→구현) 프로젝트를 만들 수 있다 | Phase 3 |
| US-D3 | P1 | 개발자로서, 대화 도중 창을 닫아도 다음에 이어서 진행할 수 있다 | Phase 3 |
| US-D4 | P1 | 개발자로서, AI가 만든 파일이 저장되고 진행 상황을 볼 수 있다 | Phase 4 |
| US-D5 | P1 | 개발자로서, 완성된 프로젝트를 고유 URL로 열람하고 공개범위(비공개/링크공개/전체공개)를 정할 수 있다 | Phase 5 |
| US-D6 | P2 | 개발자로서, 체험 7일이 지나면 결제해야 계속 쓸 수 있다 | Phase 6 |
| US-D7 | P3 | 개발자로서, 내 프로젝트의 버그를 프롬프트로 설명하면 SDVC 엔진이 직접 고쳐준다 | Phase 7 |
| US-D8 | P3 | 개발자로서, 이미 만든 프로젝트에 기능을 추가 요청할 수 있다 | Phase 7 |
| US-D9 | P3 | 개발자로서, 수정이 잘못됐을 때 이전 버전으로 되돌릴 수 있다 | Phase 7 |
| US-D10 | P3 | 개발자로서, SDVC 플랫폼 자체의 문제를 서버관리자에게 신고할 수 있다 | Phase 7→8 |
| US-D11 | P3 | 개발자로서, 완성된 프로젝트를 zip으로 내려받을 수 있다 | Phase 9 |
| US-D12 | **MVP 제외(향후)** | 개발자로서, 내 산출물에 사용자 로그인(ID/비밀번호)을 넣고, 그 회원을 등록·삭제 등으로 직접 관리할 수 있다 — "산출물 회원기능". 2026-09-08 MVP 제외 결정, 2026-09-10 범위 재확인(MVP 이후 유지) | Phase 9 이후(별도 설계 필요) |

### 사용자 (개발자가 만든 산출물의 방문자 — SDVC와 직접 계약 없음)

| ID | 우선순위 | 내용 | 관련 Phase |
|---|---|---|---|
| US-U1 | P1 | 사용자로서, 공개되거나 링크를 아는 산출물을 로그인 없이 브라우저로 바로 열람할 수 있다 | Phase 5 |

### 서버관리자 (플랫폼 운영자, 나)

| ID | 우선순위 | 내용 | 관련 Phase |
|---|---|---|---|
| US-A1 | P3 | 서버관리자로서, 전체 개발자 목록·등급·구독상태를 조회하고 체험연장·정지를 할 수 있다 | Phase 8 |
| US-A2 | P3 | 서버관리자로서, 개발자별 사용량·API 원가를 모니터링하고 상한을 설정할 수 있다 | Phase 8 |
| US-A3 | P3 | 서버관리자로서, 개발자의 플랫폼 신고를 접수·처리할 수 있다 | Phase 8 |
| US-A4 | P3 | 서버관리자로서, 문제 있는 산출물·계정을 즉시 차단할 수 있다 | Phase 8 |
| US-A5 | P3 | 서버관리자로서, 자기 프로젝트를 만들려면 개발자로 겸직 등록해야 한다(서버관리자 자격으로는 불가) | Phase 9 |

## 기능 요구사항 (FR)

| ID | 내용 |
|---|---|
| FR-001 | 이메일 회원가입·로그인 (개발자), 서버관리자는 별도 절차 + 2단계 인증 |
| FR-002 | 3계층(서버관리자/개발자/사용자) × 계층별 등급에 따른 접근권한 통제 — `docs/permissions.md` 매트릭스 근거 |
| FR-003 | SDVC 대화형 엔진: 헌장→명세→명확화→계획(승인게이트)→작업분해(승인게이트)→구현(TDD)을 웹 채팅으로 진행, 예시 답안 함께 제시 |
| FR-004 | 대화·진행 상태 DB 저장 — 세션이 끊겨도 이어서 진행 |
| FR-005 | AI가 생성한 프로젝트 파일(HTML/CSS/JS)을 Storage에 저장, 버전 보관 |
| FR-006 | 프로젝트별 고유 URL(`/site/{slug}`)로 산출물 서빙 |
| FR-007 | 산출물 공개범위 설정: 비공개 / 링크공개 / 전체공개 (기본값 비공개) |
| FR-008 | 가입 후 7일 체험, 만료 시 서버가 자동으로 접근 차단(클라이언트 판정 아님) |
| FR-009 | Stripe 구독 결제 — 기본(월 $12, 프로젝트 3개·월 200만토큰) / 프로(월 $35, 프로젝트 10개·월 800만토큰) |
| FR-010 | 프로젝트 버그를 프롬프트로 등록 → SDVC 웹 엔진이 재현 테스트(RED) 후 직접 수정 |
| FR-011 | 기존 프로젝트에 기능 추가 요청 → 명세 보완(Specify 재실행) → 계획·구현 |
| FR-012 | 프로젝트 버전 이력 관리 및 롤백 |
| FR-013 | SDVC 플랫폼 신고 채널(개발자→서버관리자), 처리결과는 신고자에게 표시 |
| FR-014 | 서버관리자: 개발자 목록·등급·구독상태 조회, 체험연장, 계정 정지/해제 |
| FR-015 | 서버관리자: 사용량·비용 대시보드, 등급별 상한 설정 |
| FR-016 | 서버관리자: 비상 차단(Kill Switch) — 문제 산출물·계정 즉시 차단 |
| FR-017 | 감사 로그 — 서버관리자의 열람·변경 행위 기록 |
| FR-018 | 역할 겸직 — 한 계정이 서버관리자이면서 개발자일 수 있음 |
| FR-019 | 완성 프로젝트 zip 다운로드 |
| FR-020 | **(MVP 제외, 향후)** 산출물별 사용자 인증(ID/비밀번호 로그인) + 개발자용 사용자 관리 화면(등록·삭제·조회) |
| FR-021 | 회원가입 시 이메일 인증 필수(확인 메일의 링크 클릭 후 계정 활성화) |
| FR-022 | 개발자가 자기 프로젝트를 삭제할 수 있다 (등급 한도 초과 시 신규 생성을 위한 공간 확보 포함) |
| FR-023 | 구독 해지 시: 그 개발자의 모든 산출물이 즉시 비공개로 전환되고, 30일 유예 후 자동 삭제 |
| FR-024 | 서버관리자 계정은 환경변수(`ADMIN_EMAIL`)에 지정된 이메일로 가입할 때만 자동으로 서버관리자 권한이 부여됨 — 일반 가입 경로로는 생성 불가 |

## 성공 기준 (SC — 측정 가능하게)

| ID | 내용 |
|---|---|
| SC-001 | 신규 개발자가 가입 완료부터 로그인 상태 대시보드 진입까지 2분 이내 |
| SC-002 | SDVC 엔진 채팅 응답이 스트리밍으로 시작되기까지 3초 이내 |
| SC-003 | 구현 완료 후 산출물 URL 최초 로딩 3초 이내 |
| SC-004 | 체험 7일 경과 시 수동 개입 없이 자동으로 접근 차단됨 |
| SC-005 | 결제 성공 후 1분 이내 등급이 반영되어 한도가 늘어남 |
| SC-006 | 서버관리자가 전체 개발자 목록을 화면 하나에서 조회 가능 |
| SC-007 | 등급별 요금 대비 실제 API 원가 비율을 서버관리자가 대시보드에서 상시 확인 가능 |
| SC-008 | 프로젝트 버그 수정 시 재현 테스트(RED)가 먼저 실행된 기록이 남음 |

## 이번엔 만들지 않는 것 (Out of Scope — MVP 기준)

- **산출물 자체의 회원가입·로그인 기능** ("산출물 회원" 등급, FR-020/US-D12) — 개발자가 만든 홈페이지에 방문자 로그인 기능은 MVP에 넣지 않음. 대신 공개범위 3단계로 대체.
  **2026-09-10 재확인**: 나중에(Phase 9 이후) 만들 때는 사용자가 ID/비밀번호로 로그인하고, 그 회원의 등록·삭제 등 관리는 **개발자**가 담당하는 구조로 설계한다 — 서버관리자가 아니라 개발자의 권한임에 주의
- **동적 서버 로직이 필요한 산출물** — MVP는 정적 사이트(HTML/CSS/JS)만 생성. 별도 백엔드가 필요한 웹앱은 향후 과제
- **다국어 UI** — 한국어만
- **모바일 네이티브 앱** — 반응형 웹만 제공
- **SDVC 플랫폼 자체의 버그 수정용 웹 관리화면** — 내 PC의 Claude Code로 수행(P8-8 결정)
- **팀/조직 단위 계정** — 개발자 1계정 = 1개인. 여러 명이 프로젝트를 공유하는 기능은 없음
- **서버관리자 다중 등급의 실제 구현** (운영자/지원) — MVP는 최고관리자 1인 체제, 등급 구분은 틀만 마련(P8-1)
