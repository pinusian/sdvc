# 08. 최종 산출물 설계서(문서) 작성 템플릿 (~30페이지 분량)

> 구현이 끝난 뒤, 프로젝트를 기록으로 남기기 위한 설계서를 작성할 때 이 템플릿을 따른다.
> 참고 원본: 『바이브코딩 실전 교육교재 — SpecKit로 기획부터 구현까지』(약 70페이지 분량, 7부 구성).
> **이 템플릿은 그 절반 수준인 A4 30페이지 내외로 간략화**한 버전이다 — 실제 프롬프트 전문을 모두 싣지 않고, 핵심 결정과 결과만 압축해서 담는다.

## 분량 배분 가이드 (총 ~30페이지)

| 부 | 제목 | 분량 | 원본 대비 |
|---|---|---|---|
| 1부 | 프로젝트 개요 | 2p | 원본 1부를 1/3로 압축 |
| 2부 | 폴더 구조 | 2p | 원본 2부를 1/4로 압축, 표 위주 |
| 3부 | 헌장~계획까지 (Constitution~Plan) | 6p | 원본 3부를 절반으로. 프롬프트 전문 대신 핵심 결정만 |
| 4부 | 작업 분해와 구현 결과 (Tasks~Implement) | 10p | 가장 비중 있게. Task 요약표 + 주요 트러블슈팅 3~5건만 |
| 5부 | 실행 방법 | 3p | `07-run-guide-template.md` 내용을 그대로 옮김 |
| 6부 | 설정(API 키 등) | 2p | 필요한 경우만 |
| 7부 | 배운 점 | 3p | 원본 7부 요약 — 이 프로젝트만의 구체적 교훈 위주 |
| 부록 | 커밋 이력 요약 | 2p | 전체 커밋이 아니라 슬라이스별 대표 커밋만 |

**원본과의 핵심 차이**: 원본 교재는 모든 실제 프롬프트 원문과 AI 응답을 그대로 기록하는 "동행 기록"이었다. 이 템플릿은 초보자가 빠르게 훑어볼 수 있도록 **결정과 근거 중심으로 압축**하고, 프롬프트는 대표적인 것 1~2개만 예시로 남긴다.

## 각 부의 작성 지침

### 1부. 프로젝트 개요 (2페이지)
- 무엇을 만들었는가 (한 문단)
- 왜 만들었는가 / 누가 쓰는가
- 사용한 기술 스택 한눈에 보는 표

### 2부. 폴더 구조 (2페이지)
- 최상위 폴더 트리 (코드 블록)
- 폴더별 역할 표 (폴더명 / 역할 1줄)
- `.env`, `requirements.txt` 등 설정 파일 위치만 짚어줌

### 3부. 헌장~계획까지 (6페이지)
각 단계마다 다음 3가지만 기록 (프롬프트 전문 대신 요약):
- **결정**: 무엇을 정했는가 (예: "TDD 필수, SQLite 사용")
- **근거**: 왜 그렇게 정했는가 (1~2문장)
- **산출물**: 어떤 파일이 만들어졌는가 (표)

Clarify 단계는 실제로 오간 질문·답 표만 넣는다 (보통 3~5행).

### 4부. 작업 분해와 구현 결과 (10페이지, 가장 비중 있게)
- 전체 Task 요약표 (Phase / User Story / Task 번호 범위 / 핵심 내용) — 원본처럼 Task 하나하나 서술하지 않고 표로 압축
- 슬라이스(User Story)별로 반 페이지씩: 무엇을 만들었는지, RED/GREEN/REFACTOR 대표 커밋 1개씩
- **트러블슈팅은 실제로 의미 있었던 3~5건만** 선별해 표로 정리 (문제/원인/교훈)
- 최종 테스트 커버리지·통과 개수 요약

### 5부. 실행 방법 (3페이지)
`07-run-guide-template.md`를 채운 내용을 그대로 옮겨온다 (사전 준비물/다운로드/백엔드/프론트엔드/배치파일/종료).

### 6부. 설정 (2페이지, 필요한 경우만)
- 외부 API를 썼다면: 키 발급 방법, `.env` 설정 방법
- 안 썼다면 이 부를 생략하고 5부에 이어 7부로 진행

### 7부. 배운 점 (3페이지)
- 이 프로젝트에서 실제로 겪은 함정과 극복 사례 2~3개
- "다음에 비슷한 프로젝트를 한다면 무엇을 다르게 할까" 한 문단
- 남겨둔 숙제(있다면) 정직하게 기록

### 부록. 커밋 이력 요약 (2페이지)
- 전체 커밋을 나열하지 않고, 슬라이스별 대표 커밋 3개(RED/GREEN/REFACTOR 각 1개)만 표로
- `git log --oneline`으로 실제 확인한 커밋 해시를 사용 (지어내지 않음)

## 산출 형식

- 기본 산출 형식은 `.docx` (Word 문서) — `docx` 스킬을 사용해 작성한다.
- 표지에 프로젝트명, 작성일, "AI바이브코딩 프로젝트로 제작" 문구를 넣는다.
- 목차(TOC)는 Heading 스타일을 사용해 자동 생성되게 한다.
- 실제 실행 화면 스크린샷이 있다면 5부(실행 방법)에 1~2장 삽입을 권장한다 (선택 사항).
